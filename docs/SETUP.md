# Подробное руководство по установке traker-mcp

Это руководство написано для тех, кто никогда не настраивал MCP-серверы.
Читайте сверху вниз — или сразу переходите к разделу [«6. Подключение к вашему
агенту»](#6-подключение-к-вашему-агенту).

---

## 0. Что такое MCP (объяснение простыми словами)

AI-ассистенты (Claude, Cursor, Copilot в VS Code и другие) умеют выполнять
«инструменты» — команды, которые за них запускает программа-посредник.
**MCP (Model Context Protocol)** — это общий стандарт таких посредников: вы
один раз подключаете «сервер», и любой AI-клиент понимает, какие команды
доступны и как их вызывать.

**traker-mcp — это такой посредник между вашим AI-ассистентом и Яндекс Трекером.**
Он запускается на вашей машине, слушает команды ассистента и дёргает
[API Трекера](https://yandex.ru/support/tracker/ru/api/about-api) от вашего имени.

```
Вы: «Найди мои задачи в очереди TREK»
  → AI-ассистент понимает, что нужен инструмент find_issues
    → MCP-сервер traker-mcp отправляет запрос к api.tracker.yandex.net
      → Трекер возвращает список задач
        → AI-ассистент показывает их вам
```

## 1. Что понадобится

Чеклист. Отметьте у себя:

- [ ] **Node.js** версии 20 или новее — среда, в которой работает сервер
- [ ] **Токен Яндекс Трекера** — «пароль» для API (раздел 3)
- [ ] **ID вашей организации** в Трекере (раздел 4)
- [ ] Сам **репозиторий traker_mcp** — скачать или склонировать (раздел 5)
- [ ] AI-клиент из списка: VS Code, Cursor, Claude Desktop, Claude Code,
      opencode, Windsurf, Zed или JetBrains IDE

Всё это бесплатное. Ничего устанавливать в сам Трекер не нужно.

## 2. Установка Node.js

Откройте терминал и проверьте, не установлено ли уже:

```bash
node -v
```

Если ответ похож на `v20.x.x`, `v22.x.x` и т.д. — всё готово, переходите к
разделу 3. Если команда не найдена — установите:

- **Любая ОС:** зайдите на [nodejs.org](https://nodejs.org) и нажмите на кнопку
  большой версии (LTS) — установщик сделает всё сам.
- **macOS (Homebrew):** `brew install node`
- **Ubuntu/Debian:**
  ```bash
  curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
  sudo apt-get install -y nodejs
  ```

Проверка после установки — снова `node -v` (может понадобиться новый терминал).

## 3. Токен Яндекс Трекера

Токен — это ключ, под которым сервер обращается к API. Есть два вида,
зависит от того, к какой организации привязан ваш Трекер.

### Как понять, какой у меня вид?

| Ваша организация | Токен | Выглядит как |
|---|---|---|
| **Яндекс 360 для бизнеса** | OAuth-токен | `y0__Ag9...` |
| **Yandex Cloud / Identity Hub** | IAM-токен | `t1.9fe3...` |

Если не уверены — начните с OAuth (раздел 3.1): он живёт годами.
IAM-токен живёт не больше **12 часов**, его нужно обновлять (раздел 3.2).

### 3.1 OAuth-токен (Яндекс 360) — рекомендую большинству

1. Зайдите на [oauth.yandex.ru](https://oauth.yandex.ru) под аккаунтом,
   от имени которого будет работать ассистент.
2. Нажмите **«Создать приложение»** → выберите
   **«Для доступа к API или отладки»** → **«Перейти к созданию»**.
3. Придумайте название (например, `traker-mcp`), укажите почту для связи.
4. В поле **«Название доступа»** начните вводить `tracker` и выберите права:
   - **«Чтение из трекера»** (`tracker:read`) — если ассистенту достаточно
     только читать задачи;
   - **«Запись в трекер»** (`tracker:write`) — если нужно создавать и менять
     задачи. Можно выбрать оба.
5. Нажмите **«Создать приложение»**.
6. Скопируйте **ClientID** приложения (пригодится в следующем шаге).
7. **Войдите** в тот же аккаунт и откройте в браузере ссылку, подставив свой
   ClientID:

   ```
   https://oauth.yandex.ru/authorize?response_type=token&client_id=ВАШ_ClientID
   ```

8. На экране появится строка вида `y0__Ag9...` — это и есть токен.
   **Скопируйте и сохраните** — он показывается один раз.

### 3.2 IAM-токен (Yandex Cloud)

⚠️ Такой токен живёт не больше **12 часов** — для постоянной работы его надо
регулярно обновлять и перезаписывать в конфиг. Для сервисных аккаунтов сначала
нужен запрос в [поддержку Трекера](https://yandex.ru/support/tracker/ru/feedback.md)
(ID организации + ID сервисного аккаунта), иначе API вернёт 401.

Как получить — в [документации Yandex Cloud IAM](https://yandex.cloud/ru/docs/iam/operations/iam-token/create):
короткая команда `yc iam create-token` или curl-запрос с OAuth-токеном Яндекса.

Если используете IAM — при генерации ссылок укажите `TRACKER_AUTH=iam`
(сервер переключит заголовки с `X-Org-ID` на `X-Cloud-Org-ID`).

## 4. ID организации

1. Откройте [tracker.yandex.ru/admin/orgs](https://tracker.yandex.ru/admin/orgs)
   (в Трекере: **Администрирование → Организации**).
2. Скопируйте значение поля **«Идентификатор»** — длинное число, например
   `12345678`.

Это значение пойдёт в переменную `TRACKER_ORG_ID`.

## 5. Сборка сервера

### Способ 0 — одной командой (macOS / Linux / WSL)

Всё из разделов ниже скрипт сделает сам — включая Node.js, если его нет:

```bash
curl -fsSL https://raw.githubusercontent.com/sdamarketing/traker_mcp/main/install.sh | bash
```

Что произойдёт: проверка системы → установка Node.js через nvm (если нужно,
после подтверждения, без sudo) → загрузка сервера в `~/.traker-mcp` → сборка
и тест → мастер настройки клиентов (раздел 6). Повторный запуск — обновление.

Хотите прочитать скрипт перед запуском — уберите `| bash` и посмотрите вывод.

### Способ 1 — вручную

```bash
git clone <адрес-репозитория>   # или скачайте ZIP и распакуйте
cd traker_mcp
npm install                     # подтянет зависимости
npm run build                   # соберёт сервер в dist/
npm run smoke                   # проверит его: "OK: ... 185 tools listed"
```

Если `npm run smoke` показал `OK` — сервер собран и работает.
API при этом не вызывается — можно проверять без токена.

## 6. Подключение к вашему агенту

### Способ 1 — мастер установки (проще всего)

```bash
npm run setup
```

Мастер всё сделает сам: проверит окружение и соберёт сервер, спросит токен
(ввод скрыт) и ID организации, **проверит ключи в API Трекера**, покажет
интерактивное меню клиентов (↑↓ выбирать · Enter подтверждать) — VS Code,
Cursor, Claude Desktop, Claude Code, opencode, Windsurf, Zed, JetBrains —
настроит выбранные клиенты — через их CLI или дописав конфиг-файл с бэкапом —
и напечатает итоговый отчёт. Можно настроить несколько клиентов подряд, а в
конце мастер предложит сохранить ключи в `.env`, чтобы не вводить их снова.

### Способ 2 — автоссылки (кнопки в браузере)

```bash
npm run links
```

Скрипт спросит токен и ID организации (или возьмёт из файла `.env` — см. ниже),
и откроет в браузере страницу **install-links.html**:

- три большие кнопки: **VS Code**, **Cursor**, **Claude Desktop** — клик
  добавляет сервер автоматически;
- готовые блоки конфигурации со **вашим** токеном и **вашими** путями для всех
  остальных клиентов: нажмите «копировать» и вставьте в нужный файл.

Дальше — разделы с точными путями и ручной настройкой для каждого клиента.

<details>
<summary>Совет: храните токен в .env (чтобы каждый раз не вводить)</summary>

Создайте файл `.env` в корне репозитория:

```
TRACKER_TOKEN=y0__ваш_токен
TRACKER_ORG_ID=12345678
```

Файл `.env` уже добавлен в `.gitignore` — он случайно не попадёт в git.
Скрипт `npm run links` прочитает его сам.
</details>

### 6.1. VS Code (GitHub Copilot Chat)

Требуется VS Code 1.99+ с включённым Copilot.

**Способ 1 — кнопка.** На странице `install-links.html` нажмите
**«Установить в VS Code»**, затем подтвердите доверие серверу в открывшемся
редакторе.

**Способ 2 — через палитру команд.** `Ctrl+Shift+P` (macOS: `Cmd+Shift+P`) →
наберите `MCP: Add Server` → следуйте мастеру.

**Способ 3 — файл конфигурации.** Откройте палитру команд →
**MCP: Open User Configuration** (сервер будет доступен во всех проектах)
и вставьте:

```json
{
  "servers": {
    "yandex-tracker": {
      "type": "stdio",
      "command": "node",
      "args": ["/ПОЛНЫЙ/ПУТЬ/К/traker_mcp/dist/index.js"],
      "env": {
        "TRACKER_TOKEN": "y0__ВАШ_ТОКЕН",
        "TRACKER_ORG_ID": "12345678"
      }
    }
  }
}
```

Или для одного проекта — тот же блок в файле `.vscode/mcp.json`.

**Перезапуск и проверка.** Откройте чат Copilot (`Ctrl+Alt+I`), убедитесь, что
в списке инструментов есть `yandex-tracker` (Configure Tools), и спросите:
*«Вызови get_current_user»*.

**Если не работает.** Палитра команд → `MCP: List Servers` → выберите
`yandex-tracker` → **Show Output** — там будут логи сервера.

<details>
<summary>Как скрыть токен в конфиге VS Code (переменные ввода)</summary>

```json
{
  "inputs": [
    {
      "type": "promptString",
      "id": "tracker-token",
      "description": "Токен Яндекс Трекера",
      "password": true
    }
  ],
  "servers": {
    "yandex-tracker": {
      "type": "stdio",
      "command": "node",
      "args": ["/ПОЛНЫЙ/ПУТЬ/К/traker_mcp/dist/index.js"],
      "env": {
        "TRACKER_TOKEN": "${input:tracker-token}",
        "TRACKER_ORG_ID": "12345678"
      }
    }
  }
}
```

VS Code спросит токен один раз при первом запуске и сохранит его в системном
хранилище.
</details>

### 6.3. Claude Desktop

**Способ 1 — кнопка** (новые версии приложения). На странице
`install-links.html` нажмите **«Установить в Claude Desktop»** и подтвердите.

**Способ 2 — файл (надёжно на любой версии).**

1. В приложении: **Settings → Developer → Edit Config** — откроется нужный файл.
   Или найдите его вручную:

   | ОС | Путь к файлу |
   |---|---|
   | macOS | `~/Library/Application Support/Claude/claude_desktop_config.json` |
   | Windows | `%APPDATA%\Claude\claude_desktop_config.json` |
   | Linux | `~/.config/Claude/claude_desktop_config.json` |

2. Вставьте блок (если в файле уже что-то есть — аккуратно добавьте только
   содержимое `mcpServers`):

```json
{
  "mcpServers": {
    "yandex-tracker": {
      "command": "node",
      "args": ["/ПОЛНЫЙ/ПУТЬ/К/traker_mcp/dist/index.js"],
      "env": {
        "TRACKER_TOKEN": "y0__ВАШ_ТОКЕН",
        "TRACKER_ORG_ID": "12345678"
      }
    }
  }
}
```

3. Сохраните и **полностью перезапустите** Claude Desktop (закрыть окно
   недостаточно — выйдите из приложения и запустите снова).

**Проверка.** Откройте чат, нажмите на иконку инструментов (молоток) —
должен появиться список из 185 инструментов `yandex-tracker`. Спросите:
*«Вызови get_current_user»*.

> 💡 Если Claude Desktop на macOS не находит `node` — проблема в том, что
> приложение запускается не из вашей оболочки. На странице `install-links.html`
> уже подставлен абсолютный путь к node — используйте её конфиг.

**Если не работает.** Логи: macOS — `~/Library/Logs/Claude/mcp-server-*.log`,
Windows — `%APPDATA%\Claude\logs\`.

### 6.4. Claude Code (терминал)

Одна команда (запускать в обычном терминале, не внутри Claude Code):

```bash
claude mcp add yandex-tracker --scope user \
  -e TRACKER_TOKEN=y0__ВАШ_ТОКЕН -e TRACKER_ORG_ID=12345678 \
  -- node /ПОЛНЫЙ/ПУТЬ/К/traker_mcp/dist/index.js
```

Что означают флаги:
- `--scope user` — сервер доступен во всех проектах (уберите, чтобы добавить
  только в текущий проект);
- `-e ПЕРЕМЕННАЯ=значение` — переменные окружения сервера;
- `--` — всё, что после этого, запускается как команда сервера.

**Проверка.**

```bash
claude mcp list      # напротив yandex-tracker должно быть ✔ Connected
claude mcp get yandex-tracker
```

Внутри сессии Claude Code работает команда `/mcp`.

### 6.7. Zed

Откройте настройки: палитра команд → `zed: open settings`, добавьте в
`settings.json` ключ `context_servers`:

```json
{
  "context_servers": {
    "yandex-tracker": {
      "command": "node",
      "args": ["/ПОЛНЫЙ/ПУТЬ/К/traker_mcp/dist/index.js"],
      "env": {
        "TRACKER_TOKEN": "y0__ВАШ_ТОКЕН",
        "TRACKER_ORG_ID": "12345678"
      }
    }
  }
}
```

> ⚠️ Обратите внимание: в Zed `command` — **строка**, а аргументы передаются
> отдельным массивом `args`. Это отличается от других клиентов.

Откройте Agent Panel → Settings: рядом с сервером должна гореть зелёная
точка. При первом вызове Zed спросит разрешение на использование инструмента.

## 7. Проверка, что всё работает

Любым агентом попросите по очереди:

1. *«Вызови инструмент get_current_user»* — вернётся ваш профиль: значит,
   токен и ID организации верные.
2. *«Найди мои задачи в Трекере»* — ассистент соберёт запрос
   `find_issues {"query": "Assignee: me()"}`.
3. *«Покажи очереди организации»* — `get_queues`.

Пока Assistant выполняет вызов, клиент попросит подтвердить использование
инструмента (можно настроить «всегда разрешать»).

## 8. Если что-то не работает

| Ошибка / симптом | Что значит и что делать |
|---|---|
| `Missing required environment variable TRACKER_TOKEN` | Сервер запущен, но переменные не переданы. Проверьте блок `env` в конфиге клиента или перегенерируйте ссылки: `npm run links`. |
| `Yandex Tracker API error 401` | Неверный токен. OAuth: создайте заново по разделу 3.1. IAM: токен старше 12 часов — выпустите новый. |
| `Yandex Tracker API error 403: Organization is not available, not ready or not found` | Неверный `TRACKER_ORG_ID`, либо у аккаунта нет доступа, либо Трекер не подключён к организации. |
| `Yandex Tracker API error 403` при чтении задач | Токен выпущен только с `tracker:read`? Проверьте права доступа пользователя в Трекере — у API те же права, что в интерфейсе. |
| `400: Один или несколько параметров запроса имеют недопустимое значение` | Скорее всего, поле не того типа (например, текст вместо id). Ошибки детально расшифрованы в ответе — ассистент их увидит. |
| Сервер «молчит» в Claude Desktop (macOS) | Классика: приложение не видит `node` из nvm/Homebrew. Решение уже в `install-links.html` — там подставлен абсолютный путь к node. |
| Инструменты не появляются | Сервер отключён в клиенте (список MCP-серверов) или клиент не перезапущен. VS Code: `MCP: List Servers`. Cursor: раздел MCP в настройках. |
| У агента «нет доступа к Трекеру» | Проверьте, что не выставлен `TRACKER_LANG=en`, если работаете с русскими названиями полей, и наоборот. И убедитесь, что очередь/задача доступны вашему аккаунту в веб-интерфейсе. |
| `npm run links` открыл пустую страницу | Откройте `install-links.html` вручную из папки репозитория в любом браузере. |

## 9. FAQ

**Это безопасно — отдавать токен ассистенту?**
Токен даёт агенту ровно те же права, что у вас в Трекере: не больше. Для
только-чтение сценариев выпускайте OAuth-токен с одним правом `tracker:read`.

**Где хранить токен?**
В `.env` (для `npm run links`), в конфиге клиента или в переменных ввода VS
Code (`${input:...}`). Не в коде и не в git.

**Я использую IAM-токен, и он «протухает» каждые 12 часов. Что делать?**
Заново выпустите токен и перегенерируйте ссылки (`npm run links`), либо
автоматизируйте обновление конфига клиента. Для постоянной работы удобнее
OAuth-токен от аккаунта Яндекс 360.

**Как обновить сам сервер?**
```bash
git pull
npm install
npm run build
```
и перезапустите агента (сервер стартует заново при каждом запуске — пересборка
подхватится автоматически).

**Можно ли подключить несколько организаций?**
Да — заведите два блока в конфиге с разными именами (например
`yandex-tracker-prod` и `yandex-tracker-test`) и разными `TRACKER_ORG_ID` /
токенами. Имена инструментов будут начинаться с имени сервера.

**Ассистент видит 185 инструментов — это много.**
Современные клиенты сами подгружают описания инструментов по мере
необходимости. Если хотите ограничить — в конфигах клиентов можно выборочно
отключать инструменты.
