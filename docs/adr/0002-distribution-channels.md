# ADR-0002: Каналы дистрибуции и транспорты

- Статус: принято
- Дата: 2026-10-05
- Задачи: YTMCP-1, YTMCP-2, YTMCP-3

## Контекст

Сервер должен быть доступен максимально удобно и при этом не размножать ручные
релизные процедуры. У нас уже были: git-клон install.sh и npm.

## Решение

Пять каналов, одна сборка:

| Канал | Артефакт | Триггер |
|---|---|---|
| curl \| bash install.sh | git-клон в ~/.traker-mcp + мастер | вручную пользователем |
| npm | `tracker-mcp` (latest) | `npm publish` вручную (2FA) |
| GitHub Packages | `@sdamarketing/tracker-mcp` | CI при релизе/вручную (GITHUB_TOKEN) |
| Official MCP Registry | `io.github.sdamarketing/tracker-mcp` | CI при релизе-теге, mcp-publisher + GitHub OIDC |
| Docker | `ghcr.io/sdamarketing/tracker-mcp` | CI при релизе-теге |

Транспорты: **stdio по умолчанию**, плюс `tracker-mcp serve --port` — Streamable HTTP
с кредами Трекера из env сервера и опциональным `MCP_AUTH_TOKEN` (bearer) для клиентов.
Проксирование токенов каждого клиента — вне скоупа (мульти-тенант не делаем).

## Причины

- OIDC-публикация исключает секреты в CI и ручные логины на машинах.
- Докер и HTTP нужны self-host сценариям и CI пайплайнам пользователей.
- npm остаётся ручным из-за 2FA (осознанный компромисс).

## Последствия

- Тег `v*` — единственный триггер релиза вторичных каналов: npm всегда публикуется
  первым вручную, затем тег, затем CI сам разносит в GH Packages / Registry / Docker.
- README держит таблицу всех каналов.
