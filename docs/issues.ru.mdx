Задачи — ядро Трекера и самая большая группа инструментов сервера. Эта страница
объясняет, какой инструмент за что отвечает, и связывает их со страницами
официальной документации API.

## Поиск задач

| Инструмент | Что делает | API |
|---|---|---|
| `find_issues` | Поиск по фильтру, строке языка запросов или query2; пагинация и scroll | [Найти задачи](https://yandex.ru/support/tracker/ru/api/issues/search-issues) |
| `count_issues` | Только количество по тем же условиям | [Подсчитать задачи](https://yandex.ru/support/tracker/ru/api/issues/count-issues) |
| `get_search_suggest` | Подсказки задач по началу названия | [Подсказки поиска](https://yandex.ru/support/tracker/ru/api/issues/get-suggest) |
| `release_search_scroll` | Освобождение ресурсов scroll-поиска | [Освободить ресурсы](https://yandex.ru/support/tracker/ru/api/issues/search-release) |

### Один источник поиска за вызов

В `find_issues` передаётся **ровно один** из параметров: `queue`, `keys`,
`filter`, `filterId`, `query`, `query2`. Приоритет при случайной комбинации:
`queue > keys > filter > query`. Определяющие документы:
[язык запросов](https://yandex.ru/support/tracker/ru/user/query-filter) и
[язык запросов 2.0](https://yandex.ru/support/tracker/ru/api/issues/query2).

Примеры строк `query` (все проверены живьём):

```
Assignee: me() Resolution: empty() "Sort by": Updated DESC
Queue: YTMCP Status: open "Sort by": Created ASC
"Queue": YTMCP Summary: ~"баг" "Sort by": Created DESC
```

### Пагинация

`find_issues` отправляет `POST /issues/_search`: источник поиска идёт в
**теле** запроса (`queue`, `keys`, `filter`, `filterId`, `query` или `query2`),
а `perPage` (по умолчанию 50) и `page` (по умолчанию 1) — в **query string
URL**. Аргумента `offset` нет: листаем по номеру страницы.

```
find_issues { query: "Queue: TREK Status: open", perPage: 100, page: 2 }
→ POST /issues/_search?perPage=100&page=2
  { "query": "Queue: TREK Status: open" }
```

`order` (например, `"+updatedAt"`, `"-created"`) уходит в теле и работает
только вместе с `filter`. При поиске через `query` сортировка задаётся в самой
строке: `"Sort by": Updated DESC`.

### Scroll-поиск (>10 000 результатов)

Обычная пагинация в API не отдаёт больше 10 000 задач на выборку. Для больших
выборок используется scroll: `find_issues` с `scrollType` (`sorted` или
`unsorted`) + `scrollTTLMillis`/`perScroll` (по умолчанию 100, максимум 1000),
ответ содержит `scrollId` и `scrollToken`, следующая страница запрашивается с
тем же токеном. По завершении —
`release_search_scroll(scrollToken, scrollId)`. См.
[прокрутку результатов](https://yandex.ru/support/tracker/ru/api/issues/search-issues#scroll).

## Жизненный цикл

| Инструмент | Что делает | API |
|---|---|---|
| `create_issue` | Создание задачи, все поля опциональны | [Создать задачу](https://yandex.ru/support/tracker/ru/api/issues/create-issue) |
| `get_issue` | Карточка задачи по ключу/id | [Параметры задачи](https://yandex.ru/support/tracker/ru/api/issues/get-issue) |
| `edit_issue` | Редактирование; `extraFields` — команды `{add, set, remove}` и пользовательские поля | [Задача / редактировать](https://yandex.ru/support/tracker/ru/api/issues/patch-issue) |
| `move_issue` | Перенос в другую очередь (ключ переприсваивается) | [Перенести задачу](https://yandex.ru/support/tracker/ru/api/issues/move-issue) |
| `get_issue_changelog` | История изменений полей | [История изменений](https://yandex.ru/support/tracker/ru/api/issues/get-changelog) |

Обязательность полей при создании смотрите в
`get_queue_fields` перед `create_issue` — очереди часто требуют
дополнительные поля. Полный список полей задачи:
[«Поля задачи»](https://yandex.ru/support/tracker/ru/api/issues/fields),
[«Тело запроса»](https://yandex.ru/support/tracker/ru/api/issues/request-fields),
[«Формат ответа»](https://yandex.ru/support/tracker/ru/api/issues/response-fields).

`queue` — **ключ** очереди (для созданной вручную — строчные латинские буквы,
например `"TREK"`), `summary` — обычная строка, `description` поддерживает
разметку YFM, а `assignee` принимает логин или id пользователя, но не имя из
списка. Сначала найдите логин через `get_users { email: "user1@example.com" }`
(или `get_user { login }`), затем передайте его `login`:

```
create_issue {
  queue: "TREK",
  summary: "Страница входа отдаёт 500 при неверном пароле",
  description: "Шаги:\n1. Открыть /login\n2. Ввести неверный пароль",
  assignee: "user1"
}
```

`queue` задачи — очередь, в которой она лежит; `project` — отдельный
необязательный основной проект (короткий id). Поиск `Queue: TREK` находит
задачи, которые **сейчас** в этой очереди — `move_issue` меняет очередь,
поэтому показанная ранее в `TREK` задача может позже оказаться с другим ключом
очереди.

Поле `project` читается по-разному на входе и на выходе. При передаче
(`create_issue` / `edit_issue`) это короткий id проекта. В ответе `get_issue`
— ссылка `{primary, secondary}`: `primary` — собственный проект задачи
(один id), `secondary` — список дополнительно связанных проектов.

```
get_issue { issueId: "TREK-123" }
→ "project": { "primary": "my-project-id", "secondary": [] }
```

Такая же форма `{primary, secondary}` используется и для других ссылок на
объекты, например `parentEntity` у сущностей в API проектов.

<Warning>Локальные поля очереди в задаче адресуются **составным id**
(`61a1b2c3…--customerSegment`), короткий ключ API отвергнет с 400. Проверено
живым прогоном.</Warning>

Пользовательские поля передаются **на верхнем уровне** `create_issue` /
`edit_issue`, а не внутри обёртки `extraFields`: `extraFields` — это
аргумент MCP, который сервер подмешивает в тело запроса как есть, поэтому
`{"extraFields": {...}}` в «сыром» JSON — ошибка, API ждёт имена полей
непосредственно.

```
// аргументы edit_issue — обе формы уходят в API как поля верхнего уровня
edit_issue {
  issueId: "TREK-123",
  priority: "blocker",
  extraFields: {
    "61a1b2c3…--customerSegment": "enterprise",   // пользовательское / локальное поле
    tags: { add: ["urgent"] }                      // команда для массива
  }
}
```

## Переходы по воркфлоу

| Инструмент | Что делает | API |
|---|---|---|
| `get_issue_transitions` | Доступные переходы из текущего статуса | [Переходы](https://yandex.ru/support/tracker/ru/api/issues/get-transitions) |
| `execute_transition` | Выполнение перехода + комментарий + резолюция | [Выполнить переход](https://yandex.ru/support/tracker/ru/api/issues/new-transition) |

<Warning>Закрытие задачи **требует резолюцию** (`fixed`, `wontFix`, `later`,
`duplicate`…) — почти в каждом воркфлоу. Список: `get_resolutions`.
Идущий без резолюции вызов отваливается 400.</Warning>

## Связи задач

| Инструмент | Что делает | API |
|---|---|---|
| `get_issue_links` | Связи задачи | [Все связи](https://yandex.ru/support/tracker/ru/api/issues/get-links) |
| `get_issue_links_paginate` | То же с пагинацией | [С пагинацией](https://yandex.ru/support/tracker/ru/api/issues/get-links-paginate) |
| `create_issue_link` | Связать задачи | [Связать задачи](https://yandex.ru/support/tracker/ru/api/issues/link-issue) |
| `delete_issue_link` | Убрать связь | [Отвязать](https://yandex.ru/support/tracker/ru/api/issues/delete-link-issue) |
| `get_link_types` | Справочник типов связей (`relates`, `depends on`…) | недокументирован, найден руками |

Направленные типы (`depends on` / `is dependent by`) в ответе видны как
`inward`/`outward` — см. примеры в самой доке.
