Помимо 187 инструментов сервер отдаёт два других MCP-примитива:
**resources** (чтение по URI, без вызова инструментов) и **prompts** (готовые
сценарии с аргументами). Это возможности версии 1.1.0+.

## Ресурсы `tracker://`

Ресурс — это «взять документ в контекст». Клиент читает его через
`resources/read`, результат — markdown, пригодный сразу для разговора.

### Шаблоны (`resources/templates/list`)

| URI | Что возвращает |
|---|---|
| `tracker://issue/{KEY}` | Карточка задачи: статус, очередь, люди, описание + **последние 20 комментариев** |
| `tracker://queue/{KEY}` | Очередь: владелец, дефолтный тип/приоритет + **обязательные поля** создания задач |
| `tracker://board/{ID}` | Доска: колонки и их статус-маппинг, WIP-лимиты |

У каждого шаблона — list-колбэк: `resources/list` показывает **мои открытые
задачи**, все очереди и все доски организации (до лимитов пагинации API).
Если API недоступен или токен мёртв — список пуст, но не ошибка JSON-RPC.

### Статические ресурсы

| URI | Что возвращает |
|---|---|
| `tracker://myself` | Ваш профиль (логин, uid, email) |
| `tracker://catalog/statuses` | Справочник статусов |
| `tracker://catalog/priorities` | Приоритеты |
| `tracker://catalog/types` | Типы задач |
| `tracker://catalog/resolutions` | Резолюции |
| `tracker://catalog/linktypes` | Типы связей задач |

Каталоги делят **10-минутный TTL-кэш** с инструментами (`src/cache.ts`) —
повторное чтение не дёргает API, а админская запись инвалидирует кэш.

### Когда ресурсы вместо инструментов

Инструмент = действие (`get_issue` — «получить и дальше работать»);
ресурс = контекст (`tracker://issue/KEY` — «прикрепить карточку к разговору»).
Для одного чтения — ресурс удобнее; для цепочки действий — инструменты.

## Промпты

Шесть готовых сценариев; в клиентах с поддержкой промптов (Claude Code,
Cursor…) вызываются как команды. Каждый результат — это немедленно исполняемый
маршрут через инструменты сервера, с уже подставленными аргументами.

| Промпт | Аргументы | Сценарий |
|---|---|---|
| `standup` | `user?` | Сделал / делаю / блокеры по задачам пользователя |
| `weekly-report` | `queue?`, `project?` | Недельный отчёт по очереди или проекту |
| `triage` | `queue`, `assignee?` | Разбор входящих задач: приоритет, ответственный, дубликаты |
| `sprint-review` | `board`, `sprint?` | Итоги спринта: сделано/не сделано/перенос |
| `close-issue` | `issue`, `resolution?`, `comment?` | Закрытие по правилам (резолюция обязательна — гард напомнит) |
| `create-issue` | `queue` | Создание с проверкой дубликатов и обязательных полей |

Пример вызова: `prompts/get` для `standup` с аргументом `{ "user": "bob" }`.

## Как это включено

Ничего включать не нужно — ресурсы и промпты регистрируются в той же
`buildServer()`, что и инструменты, и работают в обоих транспортах
(stdio и [HTTP serve](/http-server.ru)). У клиентов с интерфейсом промптов
появятся соответствующие пункты автоматически.
